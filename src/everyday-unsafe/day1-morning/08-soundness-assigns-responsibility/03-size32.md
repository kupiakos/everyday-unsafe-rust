# `Size32` Makes the Promise `unsafe`

- A lying `Eq`: a logic bug, never UB.
- `Size32` promises 4 bytes. `write_to` relies on it.
- A wrong `unsafe impl` writes out of bounds.
- Blame: the `unsafe impl`.

```rust,editable
use std::mem::MaybeUninit;

/// # Safety
///
/// Implementors must be exactly 4 bytes.
pub unsafe trait Size32 {}

// SAFETY: `u32` is exactly 4 bytes.
unsafe impl Size32 for u32 {}
// SAFETY: `f32` is exactly 4 bytes.
unsafe impl Size32 for f32 {}

pub fn write_to<T: Size32>(buf: &mut [MaybeUninit<u8>; 4], value: T) {
    // SAFETY: `T: Size32`, so `value` fits exactly in the 4 bytes of `buf`.
    // `write_unaligned` because `buf` may not be aligned for `T`.
    unsafe { buf.as_mut_ptr().cast::<T>().write_unaligned(value) };
}
```

<details>

- **Answer:** no: `unsafe` code can't rely on a safe trait's promises, so a
  lying `eq` is only a logic bug, then a promise `unsafe` code relies on must be
  an `unsafe trait`, and a wrong `unsafe impl` is at fault.

- Answer to the question on [`Eq` Can Lie](02-eq-can-lie.md): no. A lying `eq`
  gives a wrong answer, but `find`'s `unsafe` never relied on it. `unsafe` code
  can't rely on a safe trait's promises.
- Compare with `Eq`: there, a lie was the implementor's logic bug. Here, a lie
  is UB, so the promise has to be an `unsafe trait`.
- `unsafe impl Size32 for u64` compiles, and `write_to` then writes 8 bytes into
  a 4-byte buffer. The `unsafe impl` is at fault, not `write_to`.
- [`write_unaligned`](https://doc.rust-lang.org/std/primitive.pointer.html#method.write_unaligned)
  has no alignment requirement, and `buf` is only aligned for `u8`.
- `MaybeUninit<u8>` is a byte that might not be initialized. It comes back in
  [Two Fixes](../../day1-afternoon/02-reading-a-safety-section/04-two-fixes.md).
- Sharp students: `size_of::<T>() == 4` could be checked at compile time, and
  that would be better. `Size32` stands in for promises the compiler can't
  check.

</details>
